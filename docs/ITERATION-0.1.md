## 交付范围

本次实现教师/学生登录、服务端会话、班级隔离、文本材料上传、材料与知识库正文同事务入库、鉴权详情/下载，以及前端登录页和材料页。知识库只保存正文，不包含 RAG、问答、作业、超级管理员或多副本部署。

## 设计决策摘要

1. 浏览器只访问 Nginx，同源 `/api` 进入 Go 信任边界；数据库、API 端口和上传目录不对宿主机开放。
2. 使用可立即撤销的服务端会话；Cookie 仅携带带 HMAC 签名的不透明随机标识，角色和班级由服务端用户数据确认。
3. 集合查询按会话班级过滤；对象查询先取行再核对，跨班与不存在统一返回 404。
4. 文件先通过白名单、大小、UTF-8 和非空校验，再以服务端随机名落盘；两张数据表同事务，失败删除已写文件。
5. 当前限流器为进程内状态，所以 Compose 固定单 API 实例，多副本留待独立变更。

## 尚未执行的发布门禁

当前主机没有 Docker/Podman/Colima 或本地 MySQL，因此没有伪造 Compose 行为结论。以下两项必须在具备 Docker Desktop 的机器上执行后才能归档：

1. 按 README 从空卷执行 `docker compose up --build -d`，再运行 `sh scripts/verify.sh`，确认真实 MySQL 下未登录 401、教师上传 201、学生上传 403、跨班/不存在同形 404。
2. 执行一次 `docker compose down`（不加 `-v`）再启动，确认数据库与上传文件仍在。

完成后勾选 `tasks.md` 的 8.3、8.4，再运行 OpenSpec archive；当前 change 保持活动状态，避免在行为验收前把未验证实现写入长期规约。
