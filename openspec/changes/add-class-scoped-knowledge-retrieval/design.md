## Context

参见 [proposal.md](proposal.md)。当前 Go API 的 `/api/materials?q=...` 用 MySQL `LIKE` 返回材料列表，`knowledge_entries` 每份材料保存一条 UTF-8 正文；`materials`、`knowledge_entries` 都有 `class_id`。详情和下载已使用会话鉴权，跨班与不存在返回同形 404。当前为单 API 实例的 Compose 部署，MySQL 与上传卷持久化，知识库没有独立索引。

## Goals / Non-Goals

**Goals:**

- 在服务端班级边界内检索中文或英文语义相关的正文片段，并把结果可靠地映射到 MySQL 原文。
- 上传事务与检索索引解耦；索引失败可恢复，已有内容可幂等回填。
- 让用户辨别“没有命中”“正在索引”和“检索服务不可用”。

**Non-Goals:**

- 不生成问答或总结，不把检索片段解释为模型生成答案。
- 不新增跨班管理员视图、PDF/Word 解析、材料编辑或删除能力。
- 不把向量库当成材料原文或权限的权威数据库。

## Decisions

### D1：MySQL 是权威数据，内部向量库只保存可重建索引

使用 Qdrant 作为单实例 Compose 内部服务，保存片段向量及定位字段；原文、材料标题、班级归属和索引任务仍在 MySQL。向量库与本地嵌入服务都只加入内部网络，不映射宿主端口。嵌入服务使用固定版本的中英双语/多语言模型，索引与查询必须使用同一模型及维度；模型标识、维度和分块算法版本作为索引版本记录。模型文件以固定版本及校验值构建或缓存，启动时不隐式改用另一模型。对外部 SaaS 嵌入 API 的依赖会让教研正文离开本机边界，因此本方案不使用它。

相比只在现有正文上做 `LIKE`，向量索引能支持语义相近表达；代价是额外服务和最终一致性。未来可增加词法召回，但本变更只定义一个语义检索入口，现有材料列表搜索保持不变。

### D2：正文切片和稳定溯源

按 Unicode 码点切分 `knowledge_entries.content`，优先在段落/句子边界结束，设定有上限的片段长度与适度重叠；空白不会形成片段。MySQL 的 `knowledge_chunks` 保存每片的 `entry_id`、`material_id`、`class_id`、正文哈希、起止码点偏移和索引版本；片段 ID 从条目 ID、正文哈希、算法版本与偏移确定，重试时写同一 ID。Qdrant 只需保存该 ID、向量与班级过滤字段。摘录必须在读取 MySQL 原文后按偏移截取，不能直接把 Qdrant payload 当作显示正文。返回 `material_id`、标题、原始文件名、摘录和 `[start,end)` 偏移；前端打开现有材料详情并定位这段正文，显示上下文和原有鉴权下载操作。若原文版本或偏移不匹配，则丢弃该候选并安排重建。

### D3：双层班级校验与有界 API

新增 `GET /api/knowledge/search?q=...&limit=...`，经现有 `auth.Require` 认证；`q` 去首尾空白后为 1–200 个 Unicode 码点，默认 10 条、最多 20 条，非法输入 400。响应为 `{results:[...], index_state:"ready|building|degraded"}`，每条结果含稳定的片段标识、摘录、材料与偏移等来源信息。Qdrant 查询必须带会话 `class_id` payload filter 和当前索引版本，并应用经同班正负样本校准的最低相关性阈值；之后按候选 ID 从 MySQL 查片段、条目与材料，SQL 再以会话 `class_id` 限定并核对正文哈希/偏移。丢弃任何缺失、旧版或跨班候选，并在有界候选数内补足结果。向量分数只供同班排序，不返回原始向量、内部存储路径或其他班级数据。

客户端的 `class_id`、角色和片段来源参数不参与授权。用户点击引用时复用 `GET /api/materials/{id}` 和下载接口的同形 404 规则。所有检索响应沿用 `Cache-Control: no-store`；显示摘录使用文本节点，Markdown 原文沿用禁用原始 HTML 的渲染方式。

### D4：事务性索引任务与幂等补偿

在 MySQL 新增 `knowledge_index_jobs`，以 `entry_id + content_hash + index_version` 唯一标识任务，记录 `pending/processing/ready/failed`、重试时间和错误类别。教师上传仍以原来的文件、材料及知识行事务为边界，并在同一事务增加一条待索引任务；索引不阻塞已有的 201 响应。迁移后扫描所有缺少当前版本任务的已有条目，幂等补入任务。后台 worker 从 MySQL 认领任务，切片并 upsert `knowledge_chunks`、调用本地嵌入服务、按稳定 ID upsert 向量，再标记 ready；崩溃在 upsert 与标记之间时重做同一 ID。临时错误指数退避，达到阈值标记 failed 但允许人工或自动重试；版本升级或重建先建立新版本，确认后清理旧索引。

`index_state` 由当前班级的任务计算：存在失败任务为 `degraded`，否则存在待处理任务为 `building`，全部完成为 `ready`。搜索依然可返回已索引结果并显式提示状态；Qdrant 或嵌入服务无法服务请求、集合缺失或集合维度/版本不符时返回 503 和通用错误，并触发重建告警。空列表只在检索正常时表示无命中。

### D5：前端入口与定位

在现有材料页添加独立“知识库检索”模式，保留材料搜索与命令面板行为。结果卡展示摘录、标题、原文件名和来源按钮；用户选中后打开详情抽屉，按码点偏移定位并高亮对应原文。服务端仍负责所有权限判定；若来源已失效，前端显示统一“来源不可用”而不展示缓存正文。界面区分空结果、索引中、索引异常和 503，搜索输入限长并做请求取消/过期响应保护。

## Risks / Trade-offs

- **向量索引与 MySQL 非原子提交** → MySQL outbox、稳定片段 ID、重试和回填；所有候选在 MySQL 再鉴权、再截取。
- **模型或切片版本变化导致旧向量不可比** → 显式索引版本，版本不匹配时不参与查询，先回填新版本再切换。
- **语义检索有误召回或漏召回** → 显示原文摘录与可打开的来源，不承诺生成答案；用中英文、同义表达和跨班负向样本验收。
- **额外服务增加资源占用与冷启动时间** → 固定模型与资源限额，持久化模型缓存和向量卷；明确 503 与索引状态。
- **文档内容含不可信 HTML** → 摘录按纯文本渲染，详情维持现有安全 Markdown 策略。

## Migration Plan

1. 增加索引任务表和内部 Qdrant/嵌入服务配置，不更改现有材料或知识条目的 ID 与正文。迁移必须可重复执行。
2. 部署后先建立当前索引版本并回填现存种子及上传条目；在回填期间标记 `building`，旧材料读写与 `/api/materials?q=...` 继续可用。
3. 用 A/B 班账号、种子材料和新上传材料验证班级隔离、来源偏移、失败恢复，再开放前端入口。
4. 回滚应用时停止检索入口和 worker，保留 MySQL 原文与原有上传流程；向量卷及任务表可留待再部署或重建，不删除用户材料。
