## Context

参见 [proposal.md](proposal.md)。当前 Go API 的 `/api/materials?q=...` 用 MySQL `LIKE` 返回材料列表，`knowledge_entries` 每份材料保存一条 UTF-8 正文；`materials`、`knowledge_entries` 都有 `class_id`。详情和下载已使用会话鉴权，跨班与不存在返回同形 404。当前为单 API 实例的 Compose 部署，MySQL 与上传卷持久化，知识库没有独立索引。

## Goals / Non-Goals

**Goals:**

- 在服务端班级边界内支持关键字、语义和混合检索，并把结果可靠地映射到 MySQL 切片与原文。
- 上传事务与检索索引解耦；索引失败可恢复，已有内容可幂等回填。
- 有依据才调用对话模型，回答中的编号只指向本轮授权切片。
- 让用户辨别“没有命中”“正在索引”和“检索服务不可用”。

**Non-Goals:**

- 不实现流式长对话、跨班问答或交叉编码器重排序。
- 不新增跨班管理员视图、PDF/Word 解析或材料编辑能力；材料删除由关联的 `auth-upload` 能力限定权限，检索索引跟随删除失效。
- 不把向量库当成材料原文或权限的权威数据库。

## Decisions

### D1：MySQL 是权威数据，内部向量库只保存可重建索引

使用 Qdrant `campusclaw_chunks` 余弦集合保存片段向量及标识；原文、切片正文、材料标题、班级归属和索引任务留在 MySQL。Qdrant 不映射宿主端口。Go 服务通过可配置的 OpenAI 兼容课程网关分别调用嵌入和对话模型；当前课程部署分别选用 `course-embedding`（2048 维）与 `course-chat`，网关 URL、模型名、向量维度与密钥来自环境，密钥不下发浏览器或写入日志。索引与查询必须使用同一嵌入模型和维度；模型标识及切分算法作为索引版本记录。正文会发送给所配置的网关，部署文档必须说明这一数据流。

相比只在现有正文上做 `LIKE`，切片级全文索引和向量索引分别覆盖原词与语义改写。MySQL `FULLTEXT ... WITH PARSER ngram` 支持中文二元词；keyword 模式完全不依赖网关和 Qdrant。现有材料列表搜索保持不变。

### D2：正文切片和稳定溯源

`auto` 以 800 个 Unicode 码点为上限、重叠 80 个，优先在空行、换行、句号处断开；`custom` 支持 100–2000 上限、0–50% 重叠和指定分隔符，可只在待切分文本中移除 URL/邮箱或折叠空白；`hierarchy` 按 Markdown 一级至三级标题分章，过长章节再用自动窗口。种子与缺省上传使用 `auto`。MySQL 的 `knowledge_chunks` 保存切片文本、序号、`entry_id`、`material_id`、`class_id`、正文哈希、起止码点偏移、偏移基准和索引状态，并建立 ngram FULLTEXT。原始 `knowledge_entries.content` 和上传文件永不因预处理改写。若预处理改变字符位置，偏移基准明确标为 `processed`，前端不能把它误当原文件位置。

切片 ID 是 MySQL BIGINT 主键，Qdrant 点 ID 与其完全相同；Qdrant payload 只保留 class/material/entry/chunk ID 与切片序号、索引版本，不存正文。结果从已按会话班级过滤的 MySQL `chunk_text` 取摘录。重建时旧一代切片先退出可检索状态，再删除旧向量和旧切片并建立新一代，避免两代混排；失败保留原文，可重试。

### D3：双层班级校验与有界 API

新增 `GET /api/knowledge/search?q=...&mode=hybrid&limit=...`，经现有 `auth.Require`；`q` 去首尾空白后为 1–200 个码点，默认 10 条、最多 20 条。响应 `{hits:[...], message, index_state}`。keyword 路径只在 MySQL 对 `ready` 切片以 `class_id`、ngram FULLTEXT 过滤并按全文相关度排序；vector 路径先嵌入问句，再以会话班级和当前索引版本过滤 Qdrant，余弦分数低于 0.35 丢弃，然后以同一班级条件回 MySQL 核对切片状态和来源。hybrid 对两路通过阈值的候选按 RRF `1/(60+rank)` 融合；不把全文相关度和余弦分数相加。所有模式都只从 MySQL 返回正文，且限制候选和结果数量。

无候选返回 200、空 `hits` 和固定文案 `资料中未找到相关内容`。Qdrant/嵌入不可用时 keyword 仍可使用，vector/hybrid 返回 503；集合缺失或维度不符也返回 503。`index_state` 仅统计会话班级任务：有失败为 `degraded`，否则有待处理为 `building`，否则 `ready`。

客户端的 `class_id`、角色和片段来源参数不参与授权。用户点击引用时复用 `GET /api/materials/{id}` 和下载接口的同形 404 规则。所有检索响应沿用 `Cache-Control: no-store`；显示摘录使用文本节点，Markdown 原文沿用禁用原始 HTML 的渲染方式。

### D4：事务性索引任务与幂等补偿

在 MySQL 新增 `knowledge_index_jobs`，以 `entry_id + content_hash + index_version` 唯一标识任务，记录切分策略、`pending/processing/ready/failed`、租约、重试时间和错误类别。教师上传仍以原有文件、材料及知识行事务为边界，在同一事务增加待索引任务；索引不阻塞 201。迁移后对已有条目幂等补入默认 auto 任务。后台 worker 认领任务、切片并写 MySQL、调用嵌入网关、以切片 ID upsert Qdrant，最后标记切片和任务 ready；重试不生成重复可见切片。临时错误退避，达到阈值标记 failed，可经教师重建或管理命令重试。

重建接口仅允许原材料所属班级的教师调用，用户可选新策略；失效、跨班材料与未知 ID 同形 404。模型或切片版本变化时以显式重建迁移，不把旧向量与新向量混搜。

### D5：前端入口与定位

新增 `POST /api/ask`：只用最新问题做本班 hybrid 检索，取前四条；无切片直接返回固定文案及空 citations，绝不调用对话网关。有切片时，服务端组装固定 system 指令、编号、材料标题、切片序号与正文，以及有限条 user/assistant 历史；丢弃客户端 system 消息、班级声明与伪造引用。网关生成短回答，服务端校验引用编号只属于本次四条来源，返回与编号顺序一致的 citations。回答不用向量分量，也不允许网关自行检索。

在现有材料页添加分别可进入的知识检索与知识问答入口，保留材料搜索与命令面板。检索结果卡展示摘录、标题、文件名、切片序号、字符区间和来源按钮；问答界面展示短回答及可打开的来源。用户选中后打开详情抽屉。`original` 偏移可高亮，`processed` 偏移则展示处理后摘录并提示位置基准。界面区分空结果、索引中、索引异常和 503；请求取消/过期响应保护。文本和回答用安全文本渲染。若对话网关遗漏行内编号，服务端附上本轮检索来源编号供核对；若返回超出本轮范围的编号则拒绝回答。

### D6：删除材料后的检索一致性

教师删除材料时，先防止同一条目的索引任务继续写入，再按班级与知识条目 ID 清理 Qdrant 点；MySQL 以材料外键级联移除条目、切片与任务。即使遇到滞留向量候选，检索仍须通过 MySQL 原文、班级及 ready 状态复核，已删除的正文不能再次出现在结果或问答来源中。

## Risks / Trade-offs

- **向量索引与 MySQL 非原子提交** → MySQL outbox、稳定片段 ID、重试和回填；所有候选在 MySQL 再鉴权、再截取。
- **模型或切片版本变化导致旧向量不可比** → 显式索引版本，版本不匹配时不参与查询，先回填新版本再切换。
- **语义检索有误召回或漏召回** → 显示原文摘录与可打开的来源，不承诺生成答案；用中英文、同义表达和跨班负向样本验收。
- **网关延迟、费用和数据传输** → 仅服务端调用，限制输入/输出长度，超时与 503；部署前由运营者配置可信网关并确认教研数据处理边界。
- **MySQL ngram 对单字及分词边界的限制** → 文档说明关键词适用范围，用 vector/hybrid 覆盖语义改写，验收中加入中文样本。
- **文档内容含不可信 HTML** → 摘录按纯文本渲染，详情维持现有安全 Markdown 策略。

## Migration Plan

1. 增加切片、索引任务表、内部 Qdrant 和网关配置，不更改现有材料或知识条目的 ID 与正文。迁移必须可重复执行。
2. 部署后先建立当前索引版本并回填现存种子及上传条目；在回填期间标记 `building`，旧材料读写与 `/api/materials?q=...` 继续可用。
3. 用 A/B 班账号、种子材料和新上传材料验证班级隔离、来源偏移、失败恢复，再开放前端入口。
4. 回滚应用时停止检索入口和 worker，保留 MySQL 原文与原有上传流程；向量卷及任务表可留待再部署或重建，不删除用户材料。
