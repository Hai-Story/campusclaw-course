## Context

动机见 `proposal.md`。本设计基于已读取的当前代码与课程页面，不要求替换第四课底座：

- `backend/cmd/server/main.go` 使用 Go 1.22 `http.ServeMux`，认证中间件读取 Bearer Token，`auth.UserFromContext` 提供数据库中的当前角色和班级。
- MySQL 保存用户、登录 `sessions`、材料、知识条目、索引任务和切片；现有迁移采用幂等建表。登录会话不能复用作教学对话表。
- `knowledge.Service.Search` 已有班级限定、关键字/向量/混合检索、RRF 与命中回源核对；当前 SQL 和 Qdrant 仅限定班级，没有智能体材料范围。
- `knowledge/gateway.go` 的回答方法目前等待完整 JSON；新链路必须新增上游 `stream:true` 读取，不能仅把完整回答拆小输出。
- 现有前端在 `App.tsx` 的 `Library` 中有材料、检索和单次问答入口；`api.ts` 已统一 Bearer 与 `credentials:omit`，可继续复用。现有界面采用北大红、纸面底色、深浅主题及移动布局。
- Nginx `/api/` 当前没有显式关闭缓冲，CSP 仅允许同源脚本和样式；Vite 仅代理 `/api` 和 `/health`，还没有文档路由。
- `go.mod` 已有 MySQL 驱动和 sqlmock；前端已有 Vitest。两个旧 OpenSpec 变更仍在途，主 specs 尚为空。用户当前的 README 修改与未跟踪认证说明必须保留。

课程资料口径采用以下明确优先级：本课范围及最新原型 Bearer 描述优先于教程中遗留的 Cookie 说法；新会话无命中仍生成，旧 `/api/ask` 保留无依据短路。原型额外出现的班级提示词、资源收藏与演示账号接口不属于本课六项核心功能，本仓库以每智能体提示词满足教师设置要求。

## Goals / Non-Goals

**Goals:**

- 将租户边界、绑定范围、上下文预算与 SSE 事件顺序落实为可测试的服务端规则。
- 在现有单实例架构中增量迁移，保留材料 ID、Qdrant 集合、旧接口和用户数据。
- 让注解、生成文档、接口脚本、数据库断言和浏览器验收互相核对。

**Non-Goals:**

- 不实现任意工具执行、自动模型选技能、作业评分、跨班管理、注册改密、公开演示账号口令或资源收藏。
- 不实现 WebSocket、断线自动续传、多 API 副本或生产发布；POST SSE 断线由用户重新操作，不自动重复写入提问。
- 不归档旧变更，不将配置历史固化为每轮完整快照；历史引用和技能名保存当时值，会话只固定智能体 ID。

## Decisions

### 1. 在独立编排包实现智能体、技能与会话

新增 `backend/internal/tutor/`，承接解析、数据库读写、路由、提示词组装和 HTTP 会话编排；知识包仅提供范围检索和通用流式网关能力。按职责分文件，避免继续扩大 `main.go` 或把所有逻辑放进知识检索 handler。

选用此边界是因为新功能共享认证、班级、技能和会话状态，但不应让知识包依赖教学会话。相比另建微服务，当前进程内接口可复用事务和 context 取消，也不需要新部署组件。对检索和生成引入小型接口以注入测试替身；继续使用真实 MySQL 作最终一致性验收。

### 2. 六张新增表，绑定与历史各有明确归属

| 表 | 关键字段与约束 |
| --- | --- |
| `tutor_skills` | `id,class_id,name,trigger_text,subject_text,tools_json,description,source_text,enabled`；班内名称唯一 |
| `tutor_agents` | `id,class_id,name,prompt,enabled,created_at,updated_at`；班内名称唯一 |
| `tutor_agent_skills` | `agent_id,skill_id` 复合主键；删除技能级联清理绑定 |
| `tutor_agent_materials` | `agent_id,material_id` 复合主键；删除材料级联清理绑定 |
| `tutor_conversations` | `id,user_id,class_id,agent_id,title,created_at,updated_at`；按用户、班级和更新时间索引 |
| `tutor_messages` | `id,conversation_id,role,content,citations_json,skill_name,status,created_at`；按会话和 ID 索引 |

`status` 区分 `complete` 和 `incomplete`，便于解释生成中断。完整引用 JSON 保存标题、材料 ID、切片序号、摘录和偏移，避免后续索引重建改变历史证据展示。引用材料以后被删除时，历史证据快照仍能回放，打开原材料依现有授权返回 404。

智能体创建/更新在事务内校验本班技能和材料，再保存主行和替换两组绑定。绑定资源读取加锁，使验证与关联写入之间的删除不能产生部分提交；唯一约束错误转为可读 400。每轮把角色、技能和材料绑定读成一份一致配置；教师提交的新配置自下一轮生效，不要求重开会话。

相比 JSON 字段存绑定，关联表可明确约束外键、支持删除清理和材料范围查询。长度限制按 Unicode 字符在应用层检查，不依赖 UTF-8 字节数；字段使用足够大小的 TEXT 类型。

### 3. 对外路径沿用原型，旧接口保持仓库契约

| 方法与路径 | 主要请求/响应 | 授权 |
| --- | --- | --- |
| `GET /api/agents` | `{"agents":[...]}` | 已登录；学生过滤启用状态 |
| `POST /api/agents` | `name,prompt,enabled,skill_ids,material_ids` → 智能体，201 | 教师 |
| `GET /api/agents/{id}` | 智能体与绑定 | 已登录；学生隐藏停用对象 |
| `PUT /api/agents/{id}` | 完整配置替换 → 智能体，200 | 教师 |
| `GET /api/skills` | `{"skills":[...]}`，包括原文与启用状态 | 已登录、本班 |
| `GET /api/skills/{id}` | 单项技能 | 已登录、本班；补充便于原文取回 |
| `POST /api/skills` | `{"source":"..."}` → 技能，201 | 教师 |
| `PUT /api/skills/{id}` | `{"source":"..."}` → 技能，200 | 教师 |
| `DELETE /api/skills/{id}` | 204 | 教师 |
| `GET /api/conversations` | `{"conversations":[...]}` | 本人且本班 |
| `POST /api/conversations` | `{"agent_id":1}` → 会话，201 | 本人且本班 |
| `GET /api/conversations/{id}` | `conversation,messages` | 本人且本班 |
| `POST /api/conversations/{id}/messages` | `{"content":"..."}` → SSE | 本人且本班 |

新增对象路径统一使用 `{"error":"资源不存在"}` 作为未知、越界和不可选对象的 404 正文。旧材料接口保持自身已有文案，只比较同类对象的越界与不存在响应。教师写权限先于写操作业务解析判定，学生不能借非法请求获得资源存在性线索。

创建会话必须提交智能体 ID：缺失或非正整数返回 400，显式指定不可选 ID 返回 404；前端没有可用智能体时显示空状态而不提交创建。教学消息额外传入的 `agent_id,class_id,history,system` 无效，只接受 `content`，不改变服务端授权或会话绑定。

### 4. 技能采用课程文件格式与确定性单技能路由

前端文件选择器读取 `.txt/.md` 的 UTF-8 文本，与编辑框统一提交 `source`，无需增加第二套 multipart 技能写入端点。解析器先跳过前导空白和 `#` 注释；读取允许的中文字段，兼容全角/半角冒号；有效元数据后的第一处空行分隔说明。拒绝未知或重复字段；可选资料和工具为空时分别成为空过滤词和空工具列表。只接受启用「是/否」及工具白名单 `knowledge_search`；该列表不是任意工具执行入口。

路由候选按 ID 升序，从智能体当前绑定且启用的本班技能读取。按规定分隔符切词、大小写归一、忽略空词，累计子串命中分；最高分且大于零的首项胜出。保留课程确定性便于单测与复现，相比模型路由不新增外部调用或不确定结果。

默认提示词为中文学习助手；名称含「解题引导」时追加检查错误步骤、只提示下一步、不直接完成题目的服务端策略。此规则依赖模型遵循，不能声称字符串过滤能保证语义正确，因此真实模型行为另设验收项。

### 5. 范围过滤在检索候选阶段执行

扩展知识服务为独立范围查询：旧 `Search` 使用无限定材料范围；新 `SearchWithinMaterials` 接受服务端已校验的材料 IDs，空列表直接返回空结果，绝不能解释为查全班。

- 关键字 SQL 在排序和 limit 前加入参数化材料条件；不拼接来自用户的字符串。
- Qdrant 查询保留 `class_id,index_version,score_threshold`，增加 `material_id` 的 `match.any` 条件。
- 回源 MySQL 再校验班级、材料范围、切片版本、ready 状态及原文哈希；防御陈旧或异常向量候选。
- 混合检索仍采用既有 RRF，不改变全班检索语义。先取得最多四条已绑定切片，再去掉空正文与标题学科不符项，重新编号。

“先全班检索再删掉未绑定结果”的替代方案会让未绑定高分结果挤掉本来相关的绑定结果，故不采用。无绑定不调用嵌入或 Qdrant；存在绑定且依赖不可用时返回 503，不能降格为空结果。

### 6. 单轮编排与上下文预算

顺序为：校验问题与会话 → 读取会话智能体当前配置（允许已停用）→ 路由 → 保存本轮提问并更新首轮标题/时间 → 范围检索及学科过滤 → 发 meta → 组装消息 → 流式生成 → 保存助手消息 → 发 done。

取最近六条有效消息，其中当前提问已入库。先把每条截断到 500 字，再将窗口末尾的本轮用户消息替换为“编号资料 + 本轮问题”，不另外追加相同问题。每条材料最多 800 字，最多四条；用户消息明确标出材料边界。

系统消息依次包含角色、命中技能或直接回答策略、引用规则、不宣称模型身份和资料/技能数据边界。有证据要求使用有效编号；无证据要求正常回答但不得编造出处、不得输出固定的无依据整段回复。材料正文永远不进入 system。

单实例进程为每个正在生成的会话使用非阻塞占用锁；同会话并发发送返回 409，其他会话正常生成。锁在所有成功、失败和取消出口释放，限制表只保存正在生成项。这比持有跨网关数据库事务更适合当前单实例；未来多副本需另立规约引入分布式串行化。

### 7. 上游与下游都是真流式

网关请求 `/chat/completions` 时设置 `stream:true`，处理 OpenAI 兼容 SSE 的 `choices[].delta.content` 与 `[DONE]`。解析器支持 CRLF、多行 data、跨网络块 UTF-8 和空/角色片段，限制帧大小，拒绝错误响应、畸形帧、没有完成标记的截断流和空回答。

下游在完成检索后发送 meta，每帧显式 flush，并设置 `Content-Type:text/event-stream`、`Cache-Control:no-cache`、`X-Accel-Buffering:no`。引用编号清理器在流中保留尚未闭合的 `[数字` 前缀：无依据移除全部编号，有依据移除越界编号，完成时清空残留引用前缀，确保跨块也不会泄露虚构编号。发送正文与落库正文使用同一份清理结果，不在落库后再改正文。

| 事件 | JSON 数据 | 收尾语义 |
| --- | --- | --- |
| `meta` | `status:"ok",skill:{id,name}` 或 null，`citations:[...]` | 第一帧，引用先展示 |
| `delta` | `text` | 仅本次新增文本 |
| `done` | `message_id` | 完整助手消息已提交 |
| `error` | `error` | 通用失败，客户端解除忙碌状态 |

输入/归属/检索错误在 meta 前返回普通 HTTP 错误；meta 后网关错误也必须用 error，不能再发 503。生成中断有正文时保存 `incomplete`，没有正文时只保留已提交用户问题；数据库失败时不发 done，不谎称落库成功。主动取消使用请求 context 取消上游；如有正文，以脱离客户端取消、最长 3 秒的持久化 context 尽力保存 partial。

Nginx `/api/` 设置 `proxy_buffering off`、`proxy_cache off`、读超时 120 秒；Go 写超时增加至 120 秒，网关生成总超时 110 秒并响应主动取消。浏览器使用 fetch + ReadableStream 解帧，带 Bearer 而不使用只能 GET 的 EventSource；不自动重试写请求。

### 8. 前端沿用现有交互与引用查看

新增 `TutorChat.tsx` 和教师配置组件，`Library` 增加导航入口，继续复用材料详情弹层和引用定位。会话区包括已启用助手选择、新建、本人历史、消息列表、输入框、生成状态和停止按钮。发送期间禁用重复提交和切换会话，避免旧 delta 写到新会话；组件离开或登出时 abort。

管理区提供智能体完整编辑、两类绑定多选、技能原文编辑/文件导入与启停。名称重复、超长、越界绑定、空智能体、401和错误流有明确反馈；React Markdown 继续禁用原始 HTML 执行。新增组件使用现有 CSS 变量，保持移动键盘和深浅主题可用。

相比重建整套前端，复用现有导航、API 和材料阅读行为可降低回归面；页面刷新以服务端历史为准，不用浏览器存储敏感会话正文。

### 9. 注解生成 OpenAPI 3，Swagger 静态资源同源供应

新增 `backend/cmd/openapi`，使用 Go 标准库 AST 读取处理器上方结构化 `@openapi` 注解与共享 schema 定义，生成 `backend/internal/openapi/openapi.json`。注解包含方法、路径、operationId、输入输出引用、错误码和授权；生成器核对实际 mux 注册，并拒绝缺注解、重复操作或无效 schema 引用。注册关系保持可由静态生成器读取，避免动态路径拼装。

生成物由 Go embed 提供公开路由；Swagger UI 使用固定版本 `swagger-ui-dist` 的本地 JS/CSS/许可证，不从 CDN 拉取。实现阶段只在项目工具目录安装该依赖，将所需静态资产纳入 backend 构建上下文。初始化脚本放在独立同源文件中，配合现有 CSP，不开放任意外部脚本或 inline script。

Nginx `/swagger/`、`/openapi.json` 转发到 API，Vite 为开发环境补充同样代理。Swagger 展示 SSE 格式和示例；增量行为的最终验收用浏览器会话与接口测试流，不依赖 Swagger 本身的增量渲染。

相比只手写一份静态文档，注解与生成校验能发现 drift；相比 Swagger 2 输出再转换，直接生成 OpenAPI 3 可准确表达 Bearer 和 SSE，且不增加后端运行时依赖。生成器需有自身的有效/无效输入测试。

### 10. 逐接口脚本与可复现测试环境

建立 `apitest/cases/api/.../<METHOD>.py`；每个接口文件可独立执行，通过共享 fixture 取得测试用户、材料、技能、智能体与会话。`run_all.py` 自动发现脚本，按 fixture 前置关系执行，生成 `apitest/reports/` 下的 HTML；失败、环境缺失或必需用例跳过均非零退出。报告转义不可信文本，隐藏 Token、口令及连接串。

Python 的 MySQL 驱动只装到项目 `.venv`，HTTP/SSE 可复用标准库。测试连接采用专门的 `APITEST_DB_*` 配置；预检校验应用返回 ID 对应测试库数据，拒绝无数据库核对的“完整成功”。 fixture 在独立 Compose 项目名与测试卷中初始化，不读取现有 `.env` 或重用现有持久卷，结束仅清理此次建立的 fixture 或测试资源。

现有 `scripts/mock_gateway.py` 仅返回整段且没有技能差异；实现时扩展其 stream 分支、输入检查与受控失败开关，保留旧问答测试行为。mock 用于协议、隔离、落库及编排验证；真实模型另查“只引导、不报最终答案”“关闭后明显变化”“无资料仍正常回答”。课程同伴交叉验证另保留脱敏记录，不能用自身多个账号自动测试冒充同伴签认。

## Risks / Trade-offs

- [课程 Cookie 段落与任务清单不一致] → 以任务清单和原型 OpenAPI 的 Bearer 为准，复用当前认证，不恢复 Cookie。
- [参考原型与仓库旧问答字段、文案不同] → 新路径采用原型字段；旧 `/api/ask` 继续接受 `question`，旧检索继续 GET，生成文档描述实际仓库接口。
- [技能路由无法理解词表以外的意图] → 保持课程可复现规则，教师可编辑适用词；不声称覆盖所有数学问题。
- [真实模型不遵守解题引导或资料不足策略] → 加入明确服务端策略与输入边界；真实模型验收是独立门禁，mock 通过不等于语义通过。
- [上游忽略 stream 参数] → 要求 SSE 响应及增量格式，失败显式报告，不把完整 JSON 拆片冒充流式。
- [网关断开、客户端取消或数据库失败] → 保存可用 partial 与状态；只有完整落库发 done，数据库不可用时记录验证失败。
- [教师中途改变提示词、绑定或原材料] → 一轮取一致配置，下一轮生效；保存当次证据与技能名，但不承诺仅凭智能体 ID 完全复现当时提示词。
- [当前环境 PATH 没有 Go] → 实现阶段优先用只挂载当前项目的 Go 工具容器或项目内工具；环境不足明确报告，不安装系统全局依赖。
- [旧变更未勾选任务但代码已有实现] → 验证兼容性，不自动补勾、归档或扩大此次任务。

## Migration Plan

1. 实现并校验新增规约对应代码；新增表仅 `CREATE TABLE IF NOT EXISTS`，不改旧表、不重建数据卷或向量集合。
2. 在独立测试数据库执行两次迁移，确认旧用户、材料、切片与新增测试对象不被重复或覆盖；教师通过界面创建技能和智能体，未配置班级显示明确空状态。
